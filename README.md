# 王权窃贼 · Royal Thief（引擎实现）

双人回合制卡牌博弈《王权窃贼》的可运行规则引擎、边界测试与热座对战 CLI。
零依赖（Node ≥ 20，使用内置 `node --test`），不需要 `npm install`。

## 运行（网页界面）

    node server.mjs                # 启动后浏览器打开 http://localhost:8787/ （或 /web/index.html）
    node tools/build-single.mjs    # 打包两个单文件版：dist/王权窃贼.html（端游）与 dist/王权窃贼-手游.html（手游）
    node --test                    # 全套测试
    node cli/hotseat.js 1          # 热座对战（参数为随机种子）
    node cli/simulate.js --seed=1  # 用固定种子回放一整局（只打印公开信息）
    node cli/simulate.js --games=2000 --fight=0.65   # 批量自动对局，输出终局原因分布

## 网页界面（web/）

牌桌式界面，纯原生 HTML/CSS/JS，无任何前端依赖；`server.mjs` 是把项目根目录当静态站点发布的最小 HTTP 服务器（浏览器必须走 http，`file://` 下无法 import ES 模块）。

**两种打开方式（都能点得动）**

1. 双击 `dist/王权窃贼.html`（端游版）或 `dist/王权窃贼-手游.html`（手游版）—— 单文件版，CSS/JS 全部内联，免服务器（推荐，直接玩就选这个）。
2. `node server.mjs` 后访问 `http://localhost:8787/`（等价于 `http://localhost:8787/web/index.html`；手机上打开 `http://<电脑IP>:8787/web/mobile.html`）。

**不要**双击 `web/index.html`：`file://` 下浏览器拒绝加载 ES 模块，页面只会渲染空壳、按钮点不动。`web/index.html` 里的普通脚本（非 module）会立刻检测这种情况并弹出红色诊断条，直接给出上面两条出路和一个可点的单文件版链接；若引擎因别的原因没起来（脚本 404、语法错误等），2.5 秒后也会自动把原因和排查步骤显示在诊断条里，不用开 F12。

**先进主界面**：打开页面先看到一张**暖色鎏金大厅**——巨大的「♛ 王权窃贼」标题、牌组构成徽章、三张模式大卡、「开始对局（当前模式）」和「规则速览」。规则只说在「规则速览」里（主界面上一句规则要点都不放，只留入口），对战界面右侧战报栏顶部也有一个「规则速览」按钮随时可查。点模式卡只切换选择（描金高亮），按「开始对局」才进入对战界面；选「联机对战」会把下面的开房面板点亮并聚焦邀请码输入框。对局中随时可以点顶栏的「主界面」回去。

三种对局方式（主界面或顶栏切换，随时可换）：

- **人机对战**：你执 A，电脑执 B。电脑行动前有约 0.6 秒停顿，方便看清它做了什么。
- **（已取消）双人热座**：网页版不再提供「两个人共用一台设备轮流操作」的模式——联机对战已经能满足两人各自看自己手牌的需求。引擎本身仍支持热座（`cli/hotseat.js` 与遮屏逻辑都还在），只是不在界面上暴露。
- **自动观战**：双方都由机器人驱动，上帝视角亮出双方手牌，适合演示与截图。
- **联机对战**：开房拿 4 位邀请码，朋友输码（或点邀请链接）进局，两台设备真人对战；服务器权威、各自只看得到自己那份快照。详见下面的「联机对战」章节。

**端游版 / 手游版分开**：`web/index.html` 是端游版；`web/mobile.html` + `web/mobile.css` + `web/mobile.js` 是手游版（触屏优先）。两者共用同一套引擎与 `web/app.js`（DOM 契约完全一致），差别只在版式与交互：手游版带 `viewport-fit=cover` 与 `env(safe-area-inset-*)` 安全区、按钮 ≥44px、手牌可横向滑动、**长按任意卡牌放大看说明**（触屏没有 hover）；**竖屏**把判定区顶到上方、提示浮在手牌上方，**横屏**把提示改成右侧竖排操作面板，左侧留给牌桌。打包脚本会同时输出两个单文件，互相之间的链接也已改写成同目录文件。

**版式（三国杀式，v5 精简）**：整张牌桌只有三块——**中间是判定区**（对战牌、身份、结算逐条播放），**右侧是常驻战报栏**（窄栏 250px，公开信息 / 我的私有提示两个页签，顶部就是「规则速览」），**底部是我的手牌**。**主牌堆在右上角、弃牌堆排在它正下方**，都是角上的小卡片，不再占桌面。所有「该你操作了」的提示分成两层，并且**同时只留一条**：

- **桌面浮层弹窗**：轮到你要做决定时，牌桌顶部弹出一条大字（「请打出一张能力牌」「请出一道角色牌」「请点一张你要留下的牌」…），**弹出即走**（约 1.6 秒后自动淡出），**新弹窗会立刻顶掉旧的**，所以永远不会有两行字叠在一起。
- **手牌右上角的操作行**：真正要点的按钮全部挂在手牌区右上角——「出战（暗置提交）」「不出战」「跳过 · 不打出功能牌」「确认选择」「重选」「取消 · 不交换」，每一条都留了退路。左边是回合状态（第 N 回合 · 谁在行动 · 止戈计数 · 牌堆是否见底），右边一行小字提示当前要做什么。**提示行不再罗列你有什么牌**。

**出牌就是点手牌**：功能牌、人牌、道具牌、以及推心置腹要交出去的那张，全部直接在手里点亮起来的那张牌上点一下即可（悬停有放大说明），操作行只负责「跳过 / 出战 / 不出战 / 确认」这类按钮。判定区左右两个槽位固定按**「对方 · 我方」**摆放（能力牌阶段两边各一个位置，打出的功能牌会在槽里停约 1.9 秒再飞进弃牌堆，不会一闪就没）。

**配色分级（看得清字）**：牌桌是**明亮的暖色石桌**（去掉了原来的深绿/近黑，整体提亮）+ 中央鎏金圆纹；浮层用深色木框 + 鎏金描边保证对比。规则是：**信息/中性 = 石板蓝**、**需要你操作 = 鎏金**、**损失/被夺走 = 砖红**、**收益/回到手里 = 青绿**。

**能力牌阶段改成双方同时（规则变更）**：能力牌阶段不再是「只有当前回合玩家能出牌」，而是**双方各有一次出牌机会**——两边各自私下选一张功能牌（或跳过），提交后不可更改，双方都提交后按 A → B 依次结算。被沉默的一方在本阶段自动视为跳过。界面上先弹「请打出一张能力牌」，你提交后变成「已暗置提交能力牌 · 等待对手提交…」，两边都交完才进入背水一战 / 对抗宣告。联机版同样如此，两个座位可以各自提交一次。

界面上的对应关系：

| 规则概念 | 界面表现 |
| --- | --- |
| 回合转换 | 每次换人先弹一条**更重的横幅**：「你的回合」/「电脑的回合」/「玩家 A 的回合」，下面写着这一回合要走的环节（抽牌 → 能力牌 → 宣告 → 结算），一眼看出换人了 |
| 抽牌阶段 | 画面上方横幅弹出「抽牌阶段」（**不在牌桌中央，避免挡住判定面板**），同时一张背面牌从主牌堆飞进行动方手牌 |
| 能力牌阶段 | **双方同时暗置**：轮到你提交时，手里能打出的功能牌会**浮起并金光呼吸**，桌面弹出大字「**请打出一张能力牌**」，**手里能打的功能牌自己在手里浮起发光，点它就直接打出**，右上角只留「跳过 · 不打出功能牌」。你提交后提示变成「已暗置提交能力牌 · 等待对手提交…」；两边都提交后才按 A → B 依次结算 |
| 推心置腹 | 选中后牌桌中央弹出大字「**请选择一张你要交换的手牌**」：**手牌里能交换的那几张会浮起来（冷色蓝光）**，直接点手牌即可；也可以点提示里的卡名，另有「取消 · 不交换」 |
| 背水一战 | 自己手牌恰好 1 张人牌时出现黄色提示（仅自己可见） |
| 对抗宣告 | **出战按钮就在手牌右上角**：到了你的宣告阶段，牌桌中央弹出大字「**请出一道角色牌**」，手牌右上角只有**两个独立按钮**（「出战（暗置提交）」／「不出战」），没有任何外框底色，**要出哪张直接在手里点**：先点人牌，再点一张道具；**两张选中牌会自动叠合成一张放到牌桌中央的出战槽，并在下面标出合成身份（骑士/匪徒/国王/贼）**。想改就点中央叠在一起的那张牌把它拆开重选；确认后按「出战（暗置提交）」。两边都只显示背面「已锁定」，双方到齐才一起翻开 |
| 战斗结算 | **更大氣、脱框、带动画**：判定区**彻底去框**（`border:0`、无底色、无阴影、无圆角），只剩牌和字；对战牌放大到 **124×146**，正中是一个**带金环徽章的 VS**，两侧的身份徽章也跟着放大，牌垫扩到 1380px 的柔和暗角。牌从手牌位置直接落在牌垫上，解释文字反而收小，视觉重心压在牌上。按 **① 同时亮牌 →（② 贼效果）→ ③ 身份克制判定 → ④ 战利品处理** 逐条播放，每步 1.1–1.8 秒，配「每一步滑入」「双方对撞 + VS 爆闪 + 冲击波」（克制判定那一步）、「贼效果时全场提亮一下」、「赢家金光上浮 / 输家压暗下沉」等动画；**点牌桌中央可立刻快进到最终结果** |
| 胜者选择 | **三国杀式点选**：两张出战牌先都压暗，鼠标移上去会亮一点，**点哪张哪张就变亮放大（1.16 倍 + 更亮的金色描边 + 绿勾）**，没选的那张只是微微压暗（不再是黑到看不清），被选中的那张下面写清楚「已选：① 留我的…」；底部提示同步变成「确认你的选择」，再点「确认选择」提交，也可以「重选」。败者只能看到卡牌最终变化（界面上只展示可观察到的卡牌去向，不暴露胜者按了哪个按钮） |
| 信息隐藏 | 顶部「战报」按钮打开右侧浮层，分「公开信息 / 我的私有提示」两个页签；沉默生效、背水一战只进私有页签。**洞若观火 / 重整的结果会当场弹成一块「窥探浮层」**（大牌 + 卡牌说明 + 「只有你能看到」），约 5 秒后自动收起，本回合内姓名旁留一个「👁 已窥探 N 张 · 点我回看」可随时点开重看；对手那一侧**完全没有提示** |
| 终局 | 全屏结算：胜负原因 + 双方手牌全部亮出（若判定动画还在播，会等播完再弹） |

**桌面浮层与手牌按钮**：判定区彻底去框（无边框、无底色、无阴影），过程文字全部去右侧战报栏；牌桌中央只在对战结算时放大成主角。

**美术**：全部是内联 SVG（零外部图片/字体/CDN，所以单文件版也能原样显示）。人物牌画成暗调油画肖像——身后是透光的石砌拱窗与窗棂，恶人背后藏刀、刀尖从肩后探出，善人是提灯的义人，皇冠是人披貂裘戴宝石冠；每张牌叠了油画颗粒、陈年清漆反光与四边内阴影，不再是平涂卡通风。牌桌是一张橡木长桌（横向木纹+板缝）并铺了一块深色皮革牌垫，**鼠标悬停任意卡牌会放大并弹出说明**；悬停主牌堆 / 弃牌堆时显示的是该堆的张数与用途。顶部两个勾选框：「牌堆张数」控制主牌堆剩余张数是否公开（默认隐藏，对应 `RULES.revealDeckCount`，勾选后才显示），「对手手牌数」控制是否公开对手手牌数量（默认隐藏，与「背水一战不泄漏手牌数量」的条款一致）。

界面逻辑通过 `test/ui.test.js` 验收：用一个极简 DOM 模拟层在 Node 里**真实执行 `web/app.js`**，驱动完一整局人机对战（点击功能牌、暗置提交、胜者选择）、验证热座传屏遮罩按人切换、观战模式双方亮牌、以及对手手牌不会出现在页面 HTML 中。

## 引擎契约

    import { createGame, apply } from './src/engine.js';

    const s = createGame(20260925);      // 固定种子 → 完全可复现
    s.pending;                           // 当前等待什么指令
    s.winner;                            // 终局结果

指令（`apply(state, cmd)`）：

| 指令 | 使用时机 |
| --- | --- |
| `{type:'PASS_FUNCTION', playerId}` | 能力牌阶段：本座位不打出功能牌（`playerId` 必填：本阶段双方各自提交） |
| `{type:'PLAY_FUNCTION', playerId, cardId, giveCardId?}` | 能力牌阶段：打出功能牌（`giveCardId` 仅推心置腹需要） |
| `{type:'DECLARE', playerId, fight, personCardId?, itemCardId?}` | 对抗宣告阶段：双方各提交一次，提交后不可修改 |
| `{type:'CHOOSE_REWARD', playerId, option:'keep'\|'take'}` | 战斗结算阶段：胜者选择处理方式 |

引擎不做任何 IO，也不阻塞等待输入：`advance()` 自动跑完所有不需要人类决策的阶段，停在 `state.pending` 上。因此同一份代码既能驱动热座 CLI，也能直接接到 WebSocket 服务端（每个连接只允许提交 `pending` 里属于该玩家的指令）。

## 信息隐藏怎么保证

- 完整状态（双方手牌、牌堆顺序）只存在于服务端内存。
- 对外只暴露 `viewFor(state, playerId)` 的结果：自己手牌明文；对手只给「是否为空」（`RULES.revealHandCounts` 可切换为公开数量）；牌堆顺序与剩余数量默认不下发。
- 事件带 `scope`：`all` 为公开提示，`private:某玩家` 只进该玩家的 `privateLog`（洞若观火结果、重整抽到的牌、沉默是否生效、背水一战判定、胜者的选项都在这一类）。界面把这些 private 事件渲染成「窥探浮层」或私有页签，但绝不会渲染到对手那一侧。
- 因此若要做联机版，只需把 `viewFor` 的结果推给对应连接，不要把 `state` 直接序列化下发。

## 规则决议的落地位置

| 决议 | 实现位置 |
| --- | --- |
| Q1 同时暗置宣告（commit-reveal） | `engine.js` `phaseDeclare` / `declare()`：两侧都提交后才 `phase='battle'` |
| Q2 贼身份锁定冻结、无克制 | `rules.js` `identityOf` 在提交时求值并存入 `declaration.identity`；`BEATS['贼'] = []` |
| Q3 出战离手期间豁免判负 | `checkZeroHands` 只在安全点调用；`declare()` 移出手牌时不校验 |
| Q4 单方出战牌返还 | `phaseBattle()` 里非对战分支先 `returnBattleCards` 再执行惩罚 |
| 平局双方弃牌（后续修订） | `phaseBattle()` 平局分支走 `discardBattleCards()`，随后 `checkZeroHands()`；开关 `RULES.drawDiscardsBattleCards` |
| Q5 止戈计数语义 | 打出 +1（上限 `RULES.zhiGeGoal`）；回合结束未打止戈则清零 |
| 止戈终局可执行（后续修订） | 止戈保持 1 张，终局阈值 `RULES.zhiGeGoal = 1`：**主牌堆见底时打出止戈即停战**，按手牌数结算 |
| Q6 功能牌不可转移 | 惩罚夺牌的候选池与推心置腹的候选池都过滤掉功能牌 |
| Q7 手牌归零场景 | 能力牌阶段/铸剑为犁/惩罚夺牌后调用 `checkZeroHands`；胜者选项 `take` 有归零护栏 |
| Q8 重整随机取人牌 | `playFunction` 的「重整」分支：`deck.filter(人牌)` 中随机取一张，其余不动 |
| Q9 僵局兜底 3 回合 | `phaseEnd()` 中 `stalemateRounds`，牌堆为空时累计，触发 `endByHands` |
| Q10 皇冠溢出公开提示 | `acquire()` 统一出口，溢出走 `scope:'all'` 事件 |

## 尚未定论 / 需要你决定的点

1. ~~止戈终局条款不可达~~ **已解决**：止戈保持全局 1 张（牌组仍 28 张），把终局阈值降为 `RULES.zhiGeGoal = 1` —— 主牌堆见底时打出止戈即停战结算（2000 局随机对局中出现 37 次，约 1.8%）。想恢复「连续两个玩家回合各打出一次止戈」的原语义，就把 `zhiGeCopies` 改 2（牌组 29 张）并把 `zhiGeGoal` 改回 2。
2. **手牌数量是否公开**：当前默认隐藏（与背水一战的隐私条款自洽）。若要公开，改 `RULES.revealHandCounts = true`，同时应从规则文本删掉隐私描述。
3. **非行动方是否吃不出战惩罚**：同时宣告模型下双方都要宣告，所以非行动方「不出战」也会掉牌，手牌消耗明显加快（27.8% 的对局是被僵局兜底结束的，说明拉锯很常见）。若想缓和，改 `RULES.passPenaltyAppliesToAllPassers = false`。
4. 平衡性：先手 A 有约 4 个百分点优势，随机策略下不算严重，值得用 `--games` 批量跑真实人类策略后再调。

## 联机对战（邀请码房间）

`server.mjs` 同时是静态网页服务器和联机房间服务器，只用 Node 内置的 `http`，没有任何第三方依赖。一条链接 + 4 位邀请码就能开局。

### 跑起来

```bash
node server.mjs        # 默认 8787 端口
node server.mjs 9000   # 换端口
```

终端会打印本机地址、局域网地址（同一 Wi-Fi 的朋友直接点这条）和联机说明。

### 开房与加入

- 主界面「联机对战」→「创建房间」→ 得到 4 位邀请码（字母表去掉了容易看错的 I O 0 1）和一条邀请链接。
- 把链接发给朋友：`http://<主机>:8787/web/index.html?room=XXXX` —— 点开就自动进房。
- 也可以在主界面输入邀请码点「加入房间」。大厅面板里有「复制邀请链接」。
- 两边到齐即开局，右上角显示当前房间号（不再是牌局种子）。
- 联机时**左右两侧按座位区分**（你永远在右侧「我方」槽、对手在左侧「对方」槽），坐 B 位也能直接点自己的手牌出牌。

### 座位 / 刷新 / 断线

- 房间只有 A、B 两个座位：先「创建房间」的是 A，用邀请码进来的是 B。
- **同一个浏览器新开标签页 = 一个新玩家**（坐 B 座），所以本机开两个标签页就能自己跟自己打一局。
- 本标签页刷新会回到原来的座位（凭证存在 `sessionStorage`）；整台机器上的房间凭证另存一份在 `localStorage`，房间满了又确实是自己崩过重开时用它抢回座位。
- 断线会自动重连；另外每 3 秒检查一次「牌局停在某个阶段、却 6 秒没收到任何推送」，发现就自己补拉一次状态 —— 丢一条推送不会卡死牌桌，也不用刷新页面。

### 联机时的规则差异

- **能力牌阶段是双方同时暗置**：两边各有一次出牌机会，各自提交后按 A → B 依次结算（被沉默的一方自动视为跳过）。
- **对抗宣告是双方同时暗置**（commit-reveal）：各自锁定自己的出战组合，两边都提交后一次性翻开。没有「谁先挂出牌」的信息差，也不会出现跨回合挂牌。
- **「不该你操作 / 指令过时」不是报错**：两边同时提交会有「快照还没到、指令已经过时」的竞态，`/api/room/act` 对这种正常流程回 **200 + ok:false**（服务器只在真异常时才 4xx/5xx），所以浏览器控制台不会刷红。
- 其余规则与人机/热座完全一致（同一套 `src/engine.js`）。

### 反作弊：服务器只下发「该给你看的那份」

`src/redact.js` 把服务端的完整 state 剪成单个座位的视角，`hub.snapshot(room, seat)` 每个座位各发一份：

- 对手手牌 → 固定 3 张占位牌，**连真实张数都不下发**（界面显示「数量未知」）；
- 主牌堆 → 占位（不给顺序）；牌局结束前不给 `winner`；
- 背水一战、私有事件（洞若观火看到的那张牌）→ 只发给本人；
- 战报/日志里的「种子 12345」统一抹掉（种子能反推整副牌序）；
- 客户端另有按 `seq` 的新旧判定：**晚到的旧快照一律丢掉**。出手后补拉的 GET 和 SSE 推送会赛跑，不判新旧就会把牌桌盖回上一阶段、卡在「等待对手」。

### 接口一览

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/room/create` | 开房，返回 `{code, seat:'A', token}` |
| POST | `/api/room/join` | 用邀请码加入，返回 `{code, seat:'B', token}` |
| GET | `/api/room/state?code&token` | 拉一次自己那份快照 |
| POST | `/api/room/act` | 提交指令 `{code, token, cmd}` |
| POST | `/api/room/rematch` | 两边同时重开一局 |
| GET | `/api/room/sse?code&token` | SSE 长连接，状态一变就推自己那份 |

安全边界：`token` 是 16 字节随机数，只凭 token 认座位；`hub.act` 校验「这个座位现在能不能动」（`canAct`）和「不许替对手提交」；房间 6 小时没人动自动回收。传输层与业务层是分开的，想换成 WebSocket 只动 `server.mjs` + `web/remote.js`。

## 部署与后续联机

- **纯静态托管**：`web/` 与 `dist/` 都是纯静态文件，直接丢到 Cloudflare Pages / GitHub Pages / 对象存储即可（游戏本身不需要后端）。要分享就发 `dist/王权窃贼-手游.html` 或部署后的 `mobile.html` 链接。
- **微信小程序**：`src/*` 引擎、`viewFor`、`RULES` 都能原样复用；要重写的是 DOM 层（`web/app.js` 的 `$()`/事件绑定换成 WXML + `setData`），`face.js` 的 SVG 需要转成小程序可渲染的图片或 `canvas`。
- **邀请码联机**：**已实现**，见上面「联机对战（邀请码房间）」。信息出口收口在 `src/redact.js` + `viewFor(state, playerId)`，永远不要把完整 `state` 直接下发。
- **放到公网**：最省事是一台小服务器/VPS 跑 `node server.mjs`，前面挂 Nginx/Caddy 反代加 HTTPS（本机 + cloudflared/frp 隧道也行），然后发链接。
- **Cloudflare**：注意 `server.mjs` 用的是「进程内内存房间 + SSE 长连接」，纯静态的 Pages 跑不了。要用 Cloudflare 就把房间搬进 Workers + Durable Objects：一个房间 = 一个 DO 实例（`src/room.js` 的状态原样搬过去），SSE 换成 WebSocket（DO 支持可休眠 WebSocket）。`src/engine.js` / `src/view.js` / `src/redact.js` 可以一行不改地复用。
- **微信小程序**：引擎照搬；小程序不支持 SSE，联机改成 `wx.connectSocket`，服务端把 SSE 端点换成 WebSocket 即可。
